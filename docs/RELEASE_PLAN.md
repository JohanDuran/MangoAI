# MangoAI v1 technical preview: plan and status

Goal: a downloadable Windows installer for technical early users (people comfortable with the Claude Code CLI and an OpenAI API
key). Free, closed source, and the installer/app take care of the environment checks. The mechanics of building and publishing are in
[RELEASING.md](RELEASING.md); this document records the decisions, what was built, and what is left.

## Decisions (answered before the work started)

| Question | Decision |
|---|---|
| Platforms | Windows 10/11 x64 only. macOS is a fast-follow (not started). |
| Distribution | A separate **public releases-only repository** (installer + checksums, no source). The source repo stays private. |
| Code signing | None for the preview. SmartScreen shows an "unknown publisher" notice; the releases README explains how to continue. |
| ffmpeg | GPL v3 build (libx264 + NVENC), pinned by version and SHA-256, shipped as a separate program with its notice. |
| Name / icon | "MangoAI". Placeholder icon generated by `scripts/make-icon.mjs` (replace `apps/desktop/assets/icon.png` any time). |

## Architecture as built

- **`apps/desktop`**: Electron shell (`contextIsolation`, `sandbox`, no node integration, CSP, navigation locked). It starts the runner as a
  child process on `127.0.0.1` (port 47175, or a free one), supervises and restarts it, stores the OpenAI key encrypted with the OS
  (`safeStorage`/DPAPI), and offers folders, diagnostics export and a Help menu.
- **Runner** (`apps/runner`): bundled and minified with esbuild into one file; dependencies stay in `node_modules`. It serves the built
  editor itself. All paths (resources, projects, logs, cache, ffmpeg, node_modules) come from `MANGO_*` environment variables, so the same
  code runs from a checkout and from the install folder.
- **Live preview without Vite**: the plan assumed the editor could be served as a static build. It cannot: the dev editor imported each
  project's generated TSX through Vite's `/@fs/` route. The runner now bundles a project's overlay on request (`GET
  /projects/:id/overlay.js`, esbuild) and the editor loads it as an ES module; react, react-dom, remotion and
  `@mangoai/remotion-overlay` are shared with the editor through `window.__MANGO_SHARED__`, so there is exactly one copy of each.
- **Exports** run Remotion's bundler from the install's `node_modules` on projects in `%APPDATA%\MangoAI\projects` (a Windows profile name
  with spaces or accents is exercised by the tests). Remotion's Chrome Headless Shell (270 MB) is shipped, so exports work offline.
- **Installer**: NSIS, per-user, no admin rights. Installer-time checks: Windows 10+, free disk space (2.5 GB), Claude CLI presence
  (informational). The app repeats and expands these on first start.

Sizes: installer 273 MB, installed 914 MB (Electron 380 MB, Chrome Headless Shell 270 MB, two ffmpeg binaries 165 MB, Remotion and
dependencies).

## What the installer and first start check

| Requirement | Where | Behaviour |
|---|---|---|
| Windows 10+ x64, 2.5 GB free | Installer | Stops with a clear message |
| Node runtime | Not needed | Electron provides it |
| ffmpeg / ffprobe | Bundled | Status panel verifies both run |
| Claude Code CLI | Installer heads-up, then Status panel | Found on PATH and in the usual install folders (`.cmd` shims too), version, and `claude auth status`; "Open installation instructions" button |
| OpenAI API key (optional) | Status panel | Validated with a free `GET /v1/models`, stored encrypted; AI features that need it say so |
| GPU encoder | Status panel | NVENC probe result, CPU fallback explained |
| Disk space | Status panel and before uploads/exports | Warns below 5 GB, refuses when an operation cannot fit |
| Export renderer | Status panel | Verifies Chrome Headless Shell is present |
| First run | App | Requirements panel opens by itself if anything is missing |

## Robustness items (from the original plan) and their status

| # | Item | Status |
|---|---|---|
| 1 | Lock down the local server | **Done, with a change**: loopback bind, Host and Origin checks, no open CORS. A per-launch token was dropped: Remotion's headless Chrome and the skills' MCP servers call the runner too, and Origin/Host checks cover the browser threats. Tested (`integration.test.ts`). |
| 2 | Validate ids | **Done**: one alphabet for project, marker and asset names; traversal tests. |
| 3 | Claude process hardening | **Done**: prompt over stdin (no 32K command-line limit), 10-minute timeout, cancel when the browser disconnects, process-tree kill, kill on shutdown. Verified with a fake CLI. |
| 4 | Classify Claude failures | **Done**: signed out / usage limit / overloaded / old CLI / timeout, with non-retryable ones stopping at once. Minimum CLI version is a warning (2.0.0, adjust when known). |
| 5 | Atomic, versioned data | **Done**: temp-file + rename writes with `.bak` recovery, `schemaVersion` and a migration hook, startup cleanup of leftovers. The "unlocked read-modify-write race" in the original plan was wrong: those operations are synchronous, so they cannot interleave in one process. |
| 6 | Packaging breakages | **Done**: skill servers use `process.execPath`; paths come from env; Remotion export runs from the install; no `shell: true`; hidden console windows. |
| 7 | Generated overlays must render | **Done**: a headless render check of three frames in the generate/retry loop (skippable with `MANGO_SKIP_RENDER_CHECK=1`; skips itself if Chrome cannot start), per-marker error boundary in the preview, loud failure during export. |
| 8 | Contain generated code | **Partly**: Electron hardening and CSP (`connect-src 'self'`) are in. Generated code still runs in the editor's origin, so it can call the local API. Isolating the preview in a separate-origin iframe is left for v1.1. |
| 9 | Cost visibility | **Done**: metered Claude cost per session in the Status panel, confirmation before generating 5 or more markers. |
| 10 | Transcription limits | **Done**: any length (30-minute pieces, stitched offsets), timeouts, retry with backoff, plain-language OpenAI errors. |
| 11 | Upload validation | **Done**: ffprobe check, rotation-aware size, temp-name upload that never replaces the current video until valid, disk-space check. |
| 12 | Export you can trust | **Done**: job with progress, cancel, disk estimate, resume after a reload, cleanup of partial files, RAM-aware concurrency. Remotion's temp bundles (about 25 MB per render) are now removed after use and swept at startup; this leak was found during testing. |
| 13 | Editor resilience | **Done**: connection banner, notices for failures that had no handler, unhandled-rejection reporting. Generation streams are not resumable after a reload (a run continues; the marker status refreshes). |
| 14 | Logs safe to send | **Done**: prompt text off by default, keys redacted, "Save diagnostics" file. |
| 15-17 | Tests, CI, API-key support | Tests **done** (34: unit + failure drills). CI and release workflows **written, not yet run** on GitHub. Anthropic API-key support not started (post-v1). |

## Verified here

- `npm run typecheck` (all packages), `npm test` (34 passing).
- Packaged app smoke test (`MangoAI.exe --smoke-test`): UI loads under the CSP, overlay preview renders, a real export completes. Run from
  outside the repository, from the installed copy.
- Silent install (49 s) and uninstall of the real installer; uninstall keeps user data.
- Drills: signed-out CLI, hung CLI (timeout), browser closed mid-run, corrupted `markers.json`, bad and non-video uploads, spoofed Host/Origin,
  path traversal, force-killing the app mid-export (no orphaned processes, no partial outputs), a data path with a space and an accent.
- A real Claude generation through the packaged runner (stdin prompt, skills, validation).

## Not verified / open

- **Not tested on a clean machine** without Claude Code, ffmpeg or Node. The release workflow installs and smoke-tests on a fresh
  GitHub runner, which is the closest thing; a VM pass before the first public link is still recommended.
- **The GitHub workflows have never run on GitHub.** On 2026-10-09 both were reproduced locally from a fresh clone: CI's steps
  (`npm ci`, typecheck, editor build, tests) pass, and the release build produces the installer, whose unpacked app passes
  `--smoke-test` including a real export. That pass found and fixed one blocker: `apps/desktop/build/` (license, NSIS include,
  afterPack hook) was git-ignored, so a checkout could not build the installer. The silent install step itself was not run here.
- **Remotion licensing.** Remotion is free for individuals and companies of up to three people. Whether companies larger than that who
  install this free desktop app need their own license is not addressed by Remotion's terms; see `docs/remotion-license-notes.md`
  for a summary and a draft question to Remotion. Decide before sharing widely.
- **`apps/desktop/build/license.txt` is a draft** written for this preview (now also covering AI-generated voiceovers). Replace it with
  what you actually want.
- **Not done, needs you:** the public releases repository, its `RELEASES_REPO_TOKEN` secret and `RELEASES_REPO` variable, and the first push.
- **macOS** is not built. Windows-only paths: NSIS, `ffmpeg.exe` names in `main.ts`, `taskkill`, the `.cmd` handling.
- **Size**: 273 MB download. Possible savings later: drop `@rspack` if Remotion does not need it, ship one ffmpeg binary, or download the
  Chrome shell on first export instead of shipping it.
- **Fonts** load from Google Fonts; offline they fall back to system fonts. Bundle them if that matters.
- **Auto-update, code signing, crash reporting, telemetry**: out of scope for v1 by design.
